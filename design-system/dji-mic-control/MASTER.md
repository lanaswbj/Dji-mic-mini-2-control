> 本文件是 `gui/src` 全部界面与交互的唯一事实来源（Single Source of Truth）。
> 任何组件里出现的颜色 / 间距 / 字号 / 圆角 / 阴影 / 动效时长，都必须来自这里定义的 token。

> 依据：`apple-design`（WWDC《Designing Fluid Interfaces》《The Details of UI Typography》
> 《Principles of Great Design》）+ `ui-ux-pro-max`（可访问性/触达/动效/导航规则库）。
>
> 产品类型定位（来自 ui-ux-pro-max `--domain product` 匹配）：**Smart Home / IoT Dashboard** —
> 推荐风格「Materials(半透明材质) + Minimalism」、仪表盘形态「Real-Time Monitoring」、
> 配色重心「深色中性 + 状态指示色」。

## 0. 设计意图（先定情绪，再定像素）

这是一个**常驻托盘、随时被瞥一眼**的硬件控制器，不是一个需要沉浸的内容应用。
目标情绪：**沉着、精确、可信**（calm / precise / trustworthy）。

由此推出三条不可妥协的取舍：

1. **状态优先于装饰。** 任何一屏，用户最先看到的必须是「设备在不在、电量够不够、有没有出错」。
2. **零惊吓。** 不做会让人心跳一下的动效（无大幅位移、无弹跳、无闪烁）；破坏性操作必须有确认与撤销。
3. **不藏功能。** 后端存在的每一项能力，主窗口都必须有一个地方能被发现、被理解、被控制。
   （这是本次重构最大的结构性修复：托盘菜单、全局热键、敲击手势此前在主窗口里完全不可见。）

胶囊悬浮在内容面**之上**，`--dock-clear` 保证最后一张卡片能滚到它下面去。
它是全应用唯一一处 `backdrop-filter` 真正有东西可采样的地方 —— 内容确实从它下面滚过。

**底部悬浮胶囊导航**，7 个目的地，一列扁平的 44px 方形图标，标签走 tooltip。

> **这一节曾经写的是「两级侧栏（设备 / 应用）」，那个结构已经拆掉了。** 分组标题当时的作用是把
> 「这台麦克风的设置」和「这个软件的设置」分开，但代价是窗口固定拿出 236px 去养七个从不变化的
> 文字标签，而且每个区段的排版都要迁就一个宽度随开关变化的列。七个目的地不需要分组标题来消歧，
> 图标本身就够；换来的是内容面占满整窗，以及一块能真正「浮在材质上」的 chrome。
> 设备选择器随之搬进标题栏 —— scope selector 属于 chrome，而标题栏是仅剩的 chrome。
> **胶囊本身刻意不可拖拽排序**（用户明确要求），理由见 §3.x 与 `lib/Dock.svelte` 的文件注释：
> 那会让每一次点击都要先和「拖拽起手」做消歧，为一个没人做第二次的重排买单。
> 真正可重排的是扇形菜单的槽位，见下面第 6 区段。

| # | 区段 | 内容 | 数据来源 |
|---|------|------|----------|
| 1 | **概览** | 连接状态、接收器身份、两个发射器（电量/充电/实时电平/序列号/固件）、常用快捷开关（降噪、低切） | `snapshot()` |
| 2 | **音频** | 降噪（开关/模式/发射器按键）、低切、音频声道、安全音轨、削波控制、人声音色（按 TX） | 协议 group `音频` |
| 3 | **电源与启动** | 接收器 15 分钟自动关机、发射器 15 分钟自动关机、跟随相机开关机 | 协议 group `电源与启动` |
| 4 | **设备信息** | 免插拔外放、麦克风指示灯、磁吸前盖配色、序列号/固件/协议版本 | 协议 group `设备` + `status.rx/tx` |
| 5 | **敲击与按键** | 敲击手势说明与实时测试、配对键实时测试、识别反馈（误判/漏判）、模型状态与增量训练、回滚/恢复出厂 | `mic_tap_*` / `pairing_button_*` |
| 6 | **快捷菜单** | Ctrl+Alt+P 说明、6 个槽位的**可拖拽排序**列表、如何用敲击/配对键操作、Claude Code 问题卡说明 | `pie_menu_slots()` + `lib/pieOrder.svelte.js` |
| 7 | **偏好设置** | 开机自启、关闭行为说明、外观（浅色/深色/跟随系统 + 窗口毛玻璃开关）、**一键注册 Claude Code 钩子**、USB 驱动状态与一键修复、关于/版本 | `app_info()` / `set_autostart()` / `claude_hooks_status()` / `set_claude_hooks()` + `lib/glass.svelte.js` |

**2–4 区段的标题与分组直接来自协议里 `Setting.group` 字段**，新增型号声明新分组时导航自动跟随，
不需要改前端 —— 与 `crates/protocol` 的 `MODELS` 注册机制保持同一条设计原则。

**第 6 区段是全应用唯一可由用户重排的列表。** 排序发生在主窗口这张静止的卡片上，**不在扇形菜单本体上**
（用户明确要求）：覆盖层是个悬在任务栏上方、只活一两秒、靠方向键/敲击驱动的东西，在它上面放拖拽，
等于让每一次弧形按压都要先和「拖拽起手」消歧 —— 而那正是全应用唯一「误判一次就把动作打进别的窗口」的控件。
存的是**稳定槽位号**（`pie_menu.rs::SLOTS[i].index`，也就是 `pie_menu_select` 里 `match` 的那个数），
所以重排永远不改变某一槽「做什么」，只改变它画在哪；「关闭」槽钉死在最后一位。

**无设备时**：1–4 区段显示统一的「未连接」空状态（含排障入口）；5–7 区段照常可用。
（旧版本没有设备时整个应用等于不可用。）

### 1.3 寻路（Wayfinding）

每一屏都必须能回答 Apple 的四问：

| 问题 | 答案所在 |
|------|----------|
| 我在哪？ | 胶囊上滑动的选中丸 + 粘性区段头标题（后者是主答案：图标导航必须有一个写着字的标题兜底） |
| 我能去哪？ | 常驻的底部胶囊，七个目的地一次全在眼前 |
| 那里有什么？ | 具体标签（「敲击与按键」而非「快捷键」），hover/聚焦时在胶囊上方浮出 |
| 怎么离开？ | Esc 关闭任何浮层；关闭窗口 = 最小化到托盘（在偏好设置里**明说**，不再是惊吓） |

| 快捷键 | 行为 |
|--------|------|
| `Ctrl+1` … `Ctrl+7` | 跳转到第 N 个区段 |
| `Ctrl+,` | 偏好设置 |

### 2.4 材质（半透明层）

Apple §12：把导航/工具栏做成**内容从下方滚过**的半透明层，而不是吃掉固定一条的实色栏。

**窗口本身是透明的，并挂了 Windows 11 的 Acrylic 背板**（`tauri.conf.json` 的
`transparent: true` + `windowEffects.effects: ["acrylic"]`）。所以下面这些 alpha 不是「在自己的底色上
再糊一层」的装饰，而是**真的把窗口后面的东西透出来**的那一层。

> **不是 Mica。** 这一节的第一版就是 Mica，结果是一个接线完全正确、却**看不见**的玻璃效果。
> Mica（`DWMSBT_MAINWINDOW`）只采样桌面壁纸，重度模糊后再往系统基色上拉，它**刻意**不显示后面的
> 任何窗口 —— 在一张普通壁纸上，它的全部贡献就是一层极淡的染色。Acrylic
> （`DWMSBT_TRANSIENTWINDOW`）模糊的是窗口背后真实的内容，那才是人们说「玻璃」时指的东西。

**间隙不上色，玻璃才有地方显形。** 内容面四周的 `--panel-gap` 间隙是**完全不绘制**的窗口本体。
这不是留白偏好，是结构必需：卡片盖住内容面、内容面盖住窗口，玻璃只能靠层层 alpha 相乘透出来，
视觉上退化成一层死板的染色。间隙是**任何卡片都盖不住的那一条**，也是唯一能让眼睛看出
「面板浮在某个东西上面」的线索 —— 而这正是材质的全部意义，均匀染色永远说不出这句话。
`body` 因此是 `transparent`，任何一处实色底都会把效果抵消掉。

> **但这条只在「背板还在」时成立。** 窗口是 `transparent: true`，玻璃一关（外观开关 / 两个 a11y 设置 /
> `setEffects` 被拒），那圈间隙就不再是材质，而是一个**直接看穿到桌面的洞** —— 实测截图里左右边缘
> 能看见后面窗口的文字，应用读起来像被剪掉了边。压平 `--glass-*` 的 alpha 够不着它，因为间隙根本
> 不画任何材质，它就是 `body`。所以间隙有自己的 token **`--window-bg`**，和那些 alpha 在同样的三个地方
> 一起翻转；关闭态取 `--surface-sunken` 而非 `--canvas`，让「面板浮在某物上」的结构在不透明时也不变形。
> 凡是依赖「窗口是透的」的东西，都要照这条办：**「玻璃关闭」是三个信号，不是一个。**

> **标题栏是这条规则的明确例外，且是应用户要求。** 它是不透明的 `--surface`（浅色主题下即纯白），
> 不吃任何 `--glass-*` alpha，也不受 外观 → 窗口毛玻璃 开关影响。
> 它曾经和间隙一样不上色，实测读作一个**洞**：应用上方横着一条桌面，应用自己的名字浮在里面，
> 按钮底下没有表面。这是全窗唯一「职责就是不半透明」的表面，因此不进下面这张表。

色值以 `R G B` 通道三元组存放（`--canvas-rgb` / `--surface-rgb` / `--raised-rgb`），
同一个颜色的不透明版与半透明版由此共用一个来源 —— 早期的面板材质是手写的 `rgba()` 字面量，
已经和 `--canvas` 悄悄对不上了。

| Token | 底色 | alpha token | 浅色 | 深色 | 用途 |
|-------|------|-------------|------|------|------|
| `--material-chrome` | `--surface-rgb` | `--glass-chrome` | 0.55 | 同 | 粘性区段头 |
| `--material-content` | `--canvas-rgb` | `--glass-content` | 0.30 | 0.34 | **内容面板 —— 全应用唯一的玻璃层** |
| `--material-card` | `--surface-rgb` | `--glass-card` | 1 | 同 | 卡片 —— **实心**，阅读发生在这里 |
| `--material-popover` | `--raised-rgb` | `--glass-popover` | 0.8 | 同 | 弹出层、下拉、Toast、对话框、**底部悬浮导航胶囊** |

`--glass-content` 是**降**到 0.30 的，不是提上去的 —— 这个方向反直觉，所以写清原因：
卡片改实心之后，面板上不再承载任何正文（区段头有自己的 `--material-chrome`），
可读性对这个 alpha 的约束整个消失了。约束一去，就该让它真正透起来：
玻璃这才在整片内容区连成一片，而不是只活在卡片之间的缝里。
深色取 0.34 而非 0.30，因为深色 Acrylic 本身更暗，同一 alpha 读上去更透，
面板需要略厚一点的 wash 才不至于读成一个洞。
（历史值：0.42 → 0.48 是当年为「高饱和壁纸下面板次级标签没有余量」买的余量；
那些次级标签已经不在这一层上了，所以那笔余量连同它的理由一起作废。）
（`--material-sidebar` / `--glass-sidebar` 随侧栏一并删除，见 §3 信息架构。）

**卡片就是玻璃那一层 —— 这条规则和第一版是反的。**
这条规则被推翻过两次，三种排布都真的 ship 过。**区别本身就是结论，别把它们合并成一句话。**

1. **实心卡片 + 厚面板（0.48）**：卡片覆盖了内容区的绝大部分面积，背板只在卡片之间的缝里
   出现 —— 名义上半透明，实际等于没有。
2. **半透明卡片（0.62）+ 同一张厚面板**：为了让背板可见，改由卡片承载玻璃。结果每一行正文
   都坐在两层 alpha 的叠加上（等效约 0.80），读作**褪色面板**而不是材质；而且它把平台惯例
   反了过来 —— Windows 11 与 macOS 都是 *chrome 是材质、内容是实心*，这里却成了唯一实心的
   表面（标题栏）框着一片透明内容。用户的原话是「毛玻璃分布有些反直觉」，指的就是这个。
   另外它还有一个几何后果：全应用最强的玻璃只存在于 8px `--panel-gap` 那一条缝里，
   而没有任何卡片能触及它 —— 最「玻璃」的一个像素是条边框，自然读成裁切痕而不是材质。
3. **当前：实心卡片（`--glass-card: 1`）+ 薄面板（0.30 / 深色 0.34）**。禁令真正约束的是
   **合并后的重量**，而消除叠加最干脆的办法不是把卡片调薄，是让它根本不参与叠加。
   卡片实心之后面板不再承载正文，于是它可以反过来变得**更透**；玻璃这才在整片内容区连成
   一片，卡片上的文字对比度也回到一个与主题无关的精确值。层级由此单调：
   **gutter（未稀释 Acrylic）→ 面板 → 卡片（实心）**，且 gutter 与面板之间的落差小到
   不再像个洞。

推论，别再单独调：`--glass-content` 不再需要和 `--glass-card` 配对调 —— 后者是 1，
唯一需要一起看的是它和「gutter 与面板的落差」。

**光泽与高光是玻璃与「褪色面板」的分界，且无法从 alpha 推导出来**：
- `--glass-sheen`：`inset 0 1px 0` 的顶边高光，材质上沿接住的光（浅色 0.7，深色 0.09）
- `--glass-gloss`：从顶面下落、45% 处归零的短渐变

两者在玻璃关闭时一并压平（`sheen` 变透明、`gloss` 变 `none`）。

> **`backdrop-filter` 看不见 OS 背板。** 这是同一个陷阱的另一半。它采样的是**页面自己**在该元素下方
> 画过的东西，所以它只属于「页面内容确实从下面滚过去」的地方：粘性区段头、弹出层、Toast、对话框。
> 挂在标题栏和旧侧栏上时，它在花 GPU 模糊一块空白矩形。`--blur-sidebar` 因此已被删除，
> 现存只有 `--blur-chrome` 和 `--blur-popover`。
> **底部导航胶囊是全窗最正当的一处**：内容面确确实实从它下面滚过去，所以它用 `--blur-popover`。

**背板只在窗口创建时应用一次，之后永不撤销；开关是纯 CSS 的。** 这是从一个失败过两次的 IPC 设计上
主动撤退的结果，两次失败方向还相反：

1. **开不回来。** `setEffects` 确实把 `DWMWA_SYSTEMBACKDROP_TYPE` 写对了，但 DWM **不会**因为这个属性
   变了就去重算一个**已经显示中**的窗口的帧 —— 用户必须先最小化再还原（或改一次窗口大小）才看得见玻璃。
   启动路径从来没这个问题，因为 `tauri.conf.json` 的 `windowEffects` 是在窗口**显示之前**应用的。
2. **在那之前，每次调用都被权限层拒绝**，而旧代码把「任何一次拒绝」都当成「背板没了」并压平 CSS ——
   于是一个配置里声明得好好的、正在正常绘制的 Acrylic，被前端亲手关成了纯不透明窗口。
   **这就是最早「毛玻璃完全没出现」的全部原因。**

现在「关闭」＝把页面画成不透明（`--window-bg` + 压平的 alpha），遮蔽程度和撤销背板完全等价，
而「开启」只是翻一个属性，下一帧生效，**没有任何可失败的环节**。代价是关闭时 DWM 仍在合成一层没人
看得见的 acrylic（一点点空闲 GPU 开销），这个代价是有意付的：不值得把一个绕合成器时序的 workaround
放在用户每天要碰的开关上。

> **同一个 DWM 怪癖在启动时也会咬人，那一半修在 Rust 里：`main.rs::reveal_backdrop`。**
> 窗口是 `"visible": false` 创建、之后再 `show()` 的（这样开机自启能直接进托盘），所以背板属性落在
> 一个 DWM 从未合成过的窗口上 —— **每次启动都是不透明的，直到用户最小化再还原**。
> `reveal_backdrop` 先重新应用一次 effect，再用
> `SetWindowPos(…, SWP_FRAMECHANGED | NOMOVE | NOSIZE | NOZORDER | NOACTIVATE)` 强制帧重算，
> 挂在两条「让窗口现身」的路径上（启动、以及托盘的 `show_main`）。两件事都做，是因为
> 「隐藏窗口上属性被忽略」和「属性存下了但从未合成」从那一侧根本区分不开。
> **任何新的「让主窗口现身」的路径都必须调它**，漏掉就会原样复现这条 bug。

> **两条 Tauri 权限事实仍然值得记住，别再踩：** `core:default` 只授予窗口的**只读** getter，
> 任何 mutation（`set_effects` / `minimize` / `start_dragging` …）都要单独列一条；
> 以及 **没有** `allow-clear-effects` —— JS 侧的 `clearEffects()` 不是另一个命令，
> 它调的是同一个 `plugin:window|set_effects`、只是把 `value` 传成 `null`。
> 按对称猜一个名字写进去，**构建脚本**会直接以 "Permission … not found" 失败：权限名是编译期校验的。
> 这同时也说明 **`npm run build` 永远验证不了 `src-tauri/`（含 `capabilities/`）的任何改动** ——
> 那半边只能用 `cargo check -p djimic-gui`。

**关掉玻璃有三个独立信号，全部落到同一个结果**：用户自己的「偏好设置 → 外观 → 窗口毛玻璃」
（`lib/glass.svelte.js`，只写 `[data-translucent="off"]`）、
`prefers-reduced-transparency: reduce`、`prefers-contrast: more`。
三者都只把 `--glass-*` 压成 1、去掉 blur、并抹掉 sheen/gloss —— 压 **alpha** 而不是逐个重写
`--material-*`，意味着以后新增一层材质会自动被覆盖，不需要有人记得回来补。

> Acrylic 跟随**系统**深浅色，不跟随本应用的「外观」覆盖项。用户强行反着设时背板会偏向另一侧，
> 这是所有挂背板的 Windows 应用的共同行为；上面的 alpha 取值留了足够的对比度余量，
> 真不喜欢的出口就是那个开关本身。

### 2.5 高度（Elevation）

| Token | 用途 |
|-------|------|
| `--elev-1` | 卡片静置 |
| `--elev-2` | hover / 拖起 |
| `--elev-3` | 弹出层、下拉、Toast |
| `--elev-4` | 模态对话框 |

深色模式的阴影需要额外加一层顶部亮边（`inset 0 1px 0 rgb(255 255 255 / 0.04)`）来替代
浅色模式里靠阴影建立的层次感 —— 纯黑阴影在深底上是不可见的。

## 3. 排版

系统字体优先（Apple §15：系统字族自带光学尺寸、字距表与易读性调优）。
`font-variant-numeric: tabular-nums` 用于所有序列号、固件号、电平百分比、电量数字 —— 数字跳动时不能抖。

### 3.1 字阶（含尺寸相关字距）

**没有任何低于 12px 的文字。** 旧代码里 9px/10px/11px 的标签全部上移。

| Token | 尺寸 / 行高 / 字距 / 字重 | 用途 |
|-------|--------------------------|------|
| `--type-display` | 28px / 1.15 / **-0.02em** / 700 | 空状态大标题（唯一一处） |
| `--type-title` | 20px / 1.25 / **-0.015em** / 650 | 区段标题（h1） |
| `--type-title-sm` | 16px / 1.35 / **-0.01em** / 620 | 卡片标题（h2） |
| `--type-body` | 14px / 1.5 / **0** / 400 | 正文、控件标签 |
| `--type-body-strong` | 14px / 1.5 / **0** / 550 | 设置项标题 |
| `--type-caption` | 13px / 1.5 / **0.005em** / 400 | 说明文字、提示 |
| `--type-label` | 12px / 1.4 / **0.06em** / 600 / uppercase | 分组眉标（唯一允许 uppercase 的一档） |

Apple §15 的核心：**字距必须随字号变化，不能一个值套所有尺寸**。
大字收紧（负字距），正文归零，小字微微放开。旧代码把 `0.05em` 同时用在 11px 和 13px 上。

### 3.2 规则

- 层级由「字号 + 字重 + 行高」三者共同构成，不能只靠字号。
- 标题层级严格递进：区段 `h1` → 卡片 `h2` → 卡内小节 `h3`。全应用**每屏只有一个 h1**。
- 间距用 `rem`/`em`，跟随用户的系统字号缩放（Dynamic Type 等价物）。
- 长文本量度上限 `72ch`。
- **图标带头、后面跟着可换行文字的那种行，一律用 `.u-icon-line`**（app.css）。
  它是 `align-items: flex-start` 加一个按行高算出来的光学微调，把图标压在**第一行**上。
  曾经有四个组件各抄了一份 `align-items: center` —— 一行时看着对，两行时图标停在段落中间。

## 4. 间距、圆角、图标

### 4.1 间距（4/8 节奏，密度档 6/10）

`--space-1:4px` `--space-2:8px` `--space-3:12px` `--space-4:16px` `--space-5:20px`
`--space-6:24px` `--space-8:32px` `--space-10:40px` `--space-12:48px`

垂直节奏分层：卡内行距 `--space-3` → 卡内小节 `--space-5` → 卡间 `--space-6` → 区段间 `--space-10`。

### 4.2 圆角

`--radius-xs:4px` `--radius-sm:6px` `--radius-md:10px` `--radius-lg:14px` `--radius-xl:20px` `--radius-full:999px`

规则：圆角随尺寸走 —— 小控件 sm，卡片 lg，对话框/浮层 xl，胶囊 full。
（旧代码有 6/7/8/10/12/18px 六种硬编码值混用。）

### 4.3 图标

- **唯一策略：内联 SVG**，24×24 viewBox，`stroke-width: 1.6`，`stroke-linecap/linejoin: round`，
  `fill: none`，颜色一律 `currentColor`。
- 尺寸 token：`--icon-sm:16px` `--icon-md:20px` `--icon-lg:24px`。**不允许出现第四种尺寸。**
- **`display: inline-block`，不是 `block`。** 块级 SVG 掉进行内上下文（`<span>文字<Icon/></span>`）
  会强行自己占一行 —— 概览「全部音频设置」按钮的箭头掉到第二行就是这么来的。
  flex / grid 会把子元素块级化，所以这个改动对现有布局零影响，只修好了行内那一种情况。
- **禁止 emoji 当图标**（明确的反模式）。旧代码里的 `🔒`（锁定）和 `⚠`（备注）必须换成 SVG。
- 同一层级不混用描边/填充两种风格。
- **图标承担导航与语义识别，不是装饰**，出现在四个固定位置：
  胶囊导航条目 / 区段头（与胶囊同一个字形，来自同一条 `nav.js` 记录）/ 卡片头（`Card` 的 `icon`，
  颜色跟随 `tone`）/ 设置行（`Row` 的 `icon`；映射表在 `SettingRow.svelte`，
  按 `Setting.id` 而非由调用方传入 —— id 是同一个设置在三块屏幕上唯一稳定的东西，
  传 prop 就得抄三份并必然漂移；查不到的 id 落回 `sliders`，新机型不改这里也能正确渲染）。
  两个「15 分钟自动关机」共用 `clock` 是有意的：图标标记的是设置的**种类**，
  具体是哪台设备由标签负责说。
- 设备渲染图（PNG 精灵图 / `import.meta.glob` 的产品图）不属于图标体系，保持原样，
  但必须有 `alt` 或 `aria-label`。

### 4.4 触达尺寸

**所有可交互元素的命中区 ≥ 32×32px**（桌面指针场景下的下限；图标视觉尺寸可以更小，靠 padding 撑开）。
标题栏窗口按钮沿用 Windows 惯例（46×32），但其余一律 ≥32。
旧代码的 22px 高标签页、24px 图标按钮、9px 字的色板按钮全部不达标。

这两个尺寸是 token，不是各组件各写一遍的字面量，划分依据是**这个东西是拿来干什么的**：

| Token | 值 | 用途 |
|---|---|---|
| `--control-h` | 32px | **用来设定一个值**的控件：Button / Switch / Segmented / 色板行。够密，一张卡里能叠好几个 |
| `--hit` | 44px | **用来瞄准**的 chrome：Dock 项、实时探针、设备图版。目标尺寸本身就是重点 |

做成 token 是因为其中一个是**承重**的：`App.svelte` 的 `--dock-clear`（最后一张卡要为悬浮 Dock 让出多少滚动余量）过去是手算的 `100px`，而这个数字完全绑在 Dock 项的 44px 上，却没有任何地方写明。现在它由 `--hit` 推导，两者不可能再各说各话——`Section.svelte` 的注释记录过同一类 bug 已经修过一次。

Toast 的关闭按钮曾是全应用唯一低于 `--control-h` 的目标（28px），且与 `AccessIssueCard` 的同一个叉号已经分叉；两处现已合并为 `lib/ui/CloseButton.svelte`。

## 5. 动效

Apple §1–§11。核心信条：**动效表达行为，不是装饰**；**从当前呈现值出发**；**可被打断**。

### 5.1 Token

| Token | 值 | 用途 |
|-------|-----|------|
| `--dur-press` | `90ms` | 按下反馈 |
| `--dur-fast` | `160ms` | hover、颜色、透明度 |
| `--dur-base` | `240ms` | 区段切换、浮层进出 |
| `--dur-spring` | `480ms` | 配 `--ease-spring` 使用（见下） |
| `--ease-out` | `cubic-bezier(0.22, 1, 0.36, 1)` | 默认缓出 |
| `--ease-in-out` | `cubic-bezier(0.65, 0, 0.35, 1)` | 可逆双向过渡 |
| `--ease-spring` | `linear(0, .114, .319, .514, .669, .781, .859, .910, .944, .965, .979, .987, .992, .995, .997, .998, 1)` | **临界阻尼弹簧**（damping 1.0，response 0.35s），采样自 `x(t)=1-(1+ωt)e^{-ωt}`，无过冲 |
| `--ease-momentum` | `cubic-bezier(0.34, 1.4, 0.44, 1)` | 仅用于「手势带着动量」的场景（本应用几乎用不到） |

> `--dur-spring` 数学上是 480ms，但弹簧的**感知时长**远短于其完全静止时间：
> 上表采样点显示 ~43% 处（约 210ms）已走完 90% 行程 —— 正落在 150–300ms 的推荐区间里。
> 这就是为什么弹簧不能按「固定时长」来判断。
>
> `linear()` 缓动需要 Chromium 113+；Windows 上 Tauri 走 WebView2（常青版），远超此要求。
> 万一不支持，自定义属性在计算值阶段失效会退回 `ease`，是可接受的降级。

### 5.2 规则

- **反馈发生在 pointer-down，不是 click。** `:active { transform: scale(0.97) }`，`--dur-press`。
  唯一例外是标题栏的三个窗口按钮：它们的职责就是**填满窗口边角**，按下时缩放会把刚填满的角又露出来，
  所以那三个只用更深的填充色表达按下。
- **只动 `transform` 和 `opacity`。** 两处曾经违反：
  - `Meter` 的遮罩过渡 `left`。概览页 250ms 轮询意味着这个布局属性每秒被重排四次 ——
    现已改为 `transform: translateX(pct%)`（百分比相对自身宽度＝轨道宽度，几何完全等价）。
  - ~~侧栏折叠过渡 `width`~~。这条「明知故犯的例外」随侧栏一起没了；现在全应用没有任何布局属性过渡。
- **选中态是一个会动的物体，不是两个背景色的交接。** 底部胶囊用一个 `.pill` 绝对定位块在图标间滑动
  （和 `Segmented` 的指示块同一套道理），位置靠 `offsetLeft/offsetWidth` **实测**而非按序号算 ——
  这样尺寸怎么变都对得上。`.item.active` 因此不带自己的背景：
  带了就会在滑动的那段时间里同时亮起两块。
- **拖拽中的东西 1:1 跟手，且不许有过渡**（Apple 直接操作原则）。「快捷菜单 → 菜单项」的被拖行
  在拖拽期间 `transition: none`，只在松手后那一小段归位时把过渡加回来；
  而且**列表在归位动画结束后才真正重排**，因为此刻它已经正好停在目标位置上，
  重排于是一帧都不动 —— 在 `pointerup` 当场提交会让它跳最多半行高。
- 进出走同一条路径（Apple §7 空间一致性）：从右侧滑入的面板必须从右侧滑出。
- 浮层的 `transform-origin` 必须锚定在触发它的元素上。
- 玻璃材质进出要「材质化」而非纯淡入：同时动 `blur` 半径和 `scale`。
- 数值型指示（电平表、电量）走 `--dur-fast` 线性过渡，不用弹簧 —— 弹簧会让读数看起来在撒谎。

### 5.3 无障碍降级（三个独立信号，全部必须处理）

```css
@media (prefers-reduced-motion: reduce) {
  /* 位移/缩放/弹簧 → 短促交叉淡入。保留有助理解的透明度变化。 */
}
@media (prefers-reduced-transparency: reduce) {
  /* 半透明材质 → 提高底色不透明度并去掉 blur。 */
}
@media (prefers-contrast: more) {
  /* 近实色背景 + 明确的高对比描边。 */
}
```

## 6. 组件契约

全部放在 `gui/src/lib/ui/`，**只依赖 token，不依赖业务数据**。

**响应式一律用容器查询，不用视口媒体查询。** 会随内容列宽度变化的规则（`Row` 的堆叠断点、
`Card` 头部换行、`Section`/`SectionHeader` 的内边距）全部写成 `@container content (…)`，
容器由 `App.svelte` 的 `.content` 用 `container: content / inline-size` 建立。
理由是实测出来的：内容列宽度从来不等于窗口宽度（`--measure-wide` 封顶，且侧栏还在的年代
760px 窗口只剩约 520px），而 `@media (max-width: 640px)` 看不见这件事 —— 于是带四个选项的分段控件
正好在它本该堆叠的尺寸上被挤成一团。视口只该管真正与窗口有关的事。

| 组件 | 契约要点 |
|------|----------|
| `Icon.svelte` | `{ name, size = "md" }`，内联 SVG 表，`currentColor`，`aria-hidden` 默认 true，`display: inline-block` |

| `Field.svelte` | 标签在控件上方或左侧且**始终可见**（禁止 placeholder 当标签） |
| `Meter.svelte` | 电平表；`role="meter"` + `aria-valuenow`；渐变来自 token |
| `StatusDot.svelte` | 状态点，**必须带同义文字**，不靠颜色单独表意 |
| `Toast.svelte` / `toasts.js` | 右下角堆叠；成功 `role="status"`、错误 `role="alert"`；**绝对定位，不推动布局** |

| `SectionHeader.svelte` | 粘性、半透明、滚动边缘渐隐（**不是** 1px 硬分隔线），且只在真的有内容滚到下面时才出现 —— 状态由滚动容器 `.content` 以继承的 `--scroll-edge` 自定义属性下发，不穿三层组件传一个布尔值 |

## 7. 反馈体系（四类，缺一不可）

Apple §16：反馈分**状态 / 完成 / 警告 / 错误**四类，各有其位置。

| 类型 | 位置 | 形态 |
|------|------|------|
| **状态**（持续） | 就地 | 标题栏设备切换器的连接点、连接徽章、实时电平、模型「训练中…」 |
| **完成**（瞬时） | 控件右侧的状态位 | `写入中` 转圈 → `已生效` 对勾（1.2s 后淡出） |
| **警告** | 就地贴着相关控件 | 「两个发射器状态不同」、「需要 v2 协议」、电量低 |
| **错误** | Toast（右下角） | `role="alert"`，含具体原因 + 「重试」按钮 |

**关键修复**：旧版把错误塞进正常文档流的 banner 里，插入时把整页往下推（布局抖动）。
新版一律用绝对定位的 Toast 栈，永不改变布局。

**每一次写入都必须有可见的中间态。** 旧版从点击到设备确认之间，除了 `cursor: progress`
什么都没有 —— 用户无法区分「正在写」和「点了没反应」。

**破坏性操作**（`mic_tap_restore_factory_model` 恢复出厂模型）必须走 `Dialog` 确认，
文案写明后果（「本地增量学习成果将被清除」），并说明该操作本身也可撤销
（后端会先备份即将被替换的文件）。

## 8. 数据与轮询策略

- 窗口隐藏到托盘时（`document.visibilityState !== "visible"`）**暂停所有轮询**。
  旧版无论窗口是否可见都以 250ms 恒定轮询，托盘常驻场景下纯属浪费。
- 分级轮询：`概览`（含实时电平）250ms；其余设备区段 1s；训练状态 2s；不可见时 0。
- 乐观更新必须有**超时兜底**：超过 3s 未被设备确认则退回真实值并报错，
  不能像旧版那样把 `noise-cancel-power` / `noise-cancel` 的 per-TX 乐观值永久留在内存里。
- `error` 状态必须能被清除（Toast 自动消失 / 用户手动关闭），不能一直挂着。

**已知的有意保留项**

- 扇形快捷菜单（`PieMenu.svelte`）的开合动画仍是手写 rAF 弹簧（`stepEase`），没有换成 CSS token 里的
  `--ease-spring`。它本来就满足「可随时打断、从当前值继续」这条最重要的原则，换成 CSS 过渡反而会退化；

- 菜单项本身仍只显示图标，不显示文字标签——弧形几何尺寸由 Rust 侧（`pie_menu.rs`）计算，加文字会牵动

  悬停/无障碍名称则通过 `aria-label` + `title` 提供。
- `shortcut.rs`（接收器按键重映射）在 Windows 上始终不可用，是从已删除的 macOS 实现留下的占位模块。
  它没有被给一个区段——一个永远显示「不可用」的导航项只是噪音。
