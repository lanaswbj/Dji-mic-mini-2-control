# DJI Mic Control — 设计系统 MASTER

> 本文件是 `gui/src` 全部界面与交互的唯一事实来源（Single Source of Truth）。
> 任何组件里出现的颜色 / 间距 / 字号 / 圆角 / 阴影 / 动效时长，都必须来自这里定义的 token。
> 组件 `<style>` 里**不允许**出现裸 hex、裸 rgba、裸 px 动效时长。
>
> 依据：`apple-design`（WWDC《Designing Fluid Interfaces》《The Details of UI Typography》
> 《Principles of Great Design》）+ `ui-ux-pro-max`（可访问性/触达/动效/导航规则库）。
>
> 产品类型定位（来自 ui-ux-pro-max `--domain product` 匹配）：**Smart Home / IoT Dashboard** —
> 推荐风格「Materials(半透明材质) + Minimalism」、仪表盘形态「Real-Time Monitoring」、
> 配色重心「深色中性 + 状态指示色」。
> 注：`--design-system` 综合查询把本项目误判成了落地页（返回 "Minimal Single Column /
> Exaggerated Minimalism"），该结果**未被采纳**；下面的体系来自产品类型匹配 + apple-design +
> 逐项人工核算，特此说明，避免后人误以为是数据库直出。

## 0. 设计意图（先定情绪，再定像素）

这是一个**常驻托盘、随时被瞥一眼**的硬件控制器，不是一个需要沉浸的内容应用。
目标情绪：**沉着、精确、可信**（calm / precise / trustworthy）。

由此推出三条不可妥协的取舍：

1. **状态优先于装饰。** 任何一屏，用户最先看到的必须是「设备在不在、电量够不够、有没有出错」。
2. **零惊吓。** 不做会让人心跳一下的动效（无大幅位移、无弹跳、无闪烁）；破坏性操作必须有确认与撤销。
3. **不藏功能。** 后端存在的每一项能力，主窗口都必须有一个地方能被发现、被理解、被控制。
   （这是本次重构最大的结构性修复：托盘菜单、全局热键、敲击手势此前在主窗口里完全不可见。）

## 1. 信息架构（IA）

### 1.1 旧结构的问题

- 「接收器快捷键」这一页实际混装了三件互不相关的事：配对键测试、敲击检测测试、机器学习模型的

（旧版本没有设备时整个应用等于不可用。）

### 1.3 寻路（Wayfinding）

每一屏都必须能回答 Apple 的四问：

| 问题 | 答案所在 |
|------|----------|
| 我在哪？ | 侧栏高亮项 + 粘性区段头标题 |
| 我能去哪？ | 常驻侧栏（不再默认折叠），两级分组 |
| 那里有什么？ | 具体标签（「敲击与按键」而非「快捷键」），侧栏项带状态徽标（如待处理反馈数） |
| 怎么离开？ | Esc 关闭任何浮层；关闭窗口 = 最小化到托盘（在偏好设置里**明说**，不再是惊吓） |

| 快捷键 | 行为 |

| `Ctrl+1` … `Ctrl+7` | 跳转到第 N 个区段 |

## 2. 颜色

全部为语义 token。**组件里不允许直接写 hex。** 深浅两套值均已逐对核算 WCAG 对比度。

### 2.1 表面与文字

| Token | 浅色 | 深色 | 用途 |
|-------|------|------|------|
| `--canvas` | `#f2f3f5` | `#121418` | 窗口底色 |
| `--surface` | `#ffffff` | `#1a1d23` | 卡片 / 面板 |
| `--surface-raised` | `#ffffff` | `#22262e` | 悬浮/弹出层、hover 态 |
| `--surface-sunken` | `#ebedf0` | `#0e1014` | 内嵌槽（分段控件底、代码块） |
| `--text` | `#16181c` | `#eceef2` | 主文字 |
| `--text-secondary` | `#5a616e` | `#98a0af` | 次要文字、说明 |
| `--text-tertiary` | `#656c79` | `#868f9f` | 区段小标题、单位、元信息 |
| `--border` | `#e0e3e8` | `#2b3039` | 常规分隔线/描边 |
| `--border-strong` | `#c6cbd4` | `#3b424e` | 需要被看见的描边（输入框、未激活轨道） |

**核算过的对比度**（相对亮度公式，非估计）：

| 组合 | 浅色 | 深色 |
|------|------|------|
| `--text` on `--surface` | **17.6:1** ✅ | **14.5:1** ✅ |
| `--text-secondary` on `--surface` | **6.2:1** ✅ | **6.4:1** ✅ |
| `--text-tertiary` on `--surface` | **5.3:1** ✅ | **5.2:1** ✅ |
| `--text-tertiary` on `--surface-sunken` | **4.50:1** ✅ | — |
| `--text-tertiary` on `--surface-raised` | — | **4.65:1** ✅ |

> 对照：旧 `--text-faint: #6d7682` 落在深色 `--bg-panel: #1e2127` 上只有约 **3.3:1**，
> 而它被用在所有分组小标题上 —— 这是必须修掉的既有缺陷，不是新增要求。

**规则**：`--text-tertiary` 是可用于正文级小字的最暗一档，禁止再新增更暗的文字色。

### 2.2 强调色

| Token | 浅色 | 深色 | 说明 |
|-------|------|------|------|
| `--accent` | `#1f6feb` | `#4d93f0` | 唯一强调色 |
| `--accent-on` | `#ffffff` | `#0e1014` | 强调色上的文字（深色模式用近黑，因为亮蓝上白字仅 3.1:1） |
| `--accent-soft` | `rgb(31 111 235 / 0.10)` | `rgb(77 147 240 / 0.16)` | 选中背景、轻量填充 |
| `--focus-ring` | `--accent` | `--accent` | 焦点环颜色 |

对比核算：浅色 `--accent-on` on `--accent` = **4.64:1** ✅；深色 `--accent-on` on `--accent` = **6.1:1** ✅。
`--accent` 作为非文字 UI 元素对 `--surface`：浅 4.64:1 / 深 5.4:1，均 ≥3:1 ✅。

### 2.3 状态色

| Token | 浅色 | 深色 | 语义 |
|-------|------|------|------|
| `--ok` / `--ok-soft` | `#1a7f4b` / 12% | `#3ecf8e` / 16% | 已连接、写入成功 |
| `--warn` / `--warn-soft` | `#9a6410` / 12% | `#e8b055` / 16% | 电量低、状态不一致、需要注意 |
| `--danger` / `--danger-soft` | `#c02626` / 12% | `#f2777a` / 16% | 错误、破坏性操作 |

**颜色永远不是唯一信号**（可访问性硬性要求）：状态点必须同时带文字，电量必须同时带图标形状变化，
「混合」状态必须同时带文字说明。

### 2.4 材质（半透明层）

Apple §12：把导航/工具栏做成**内容从下方滚过**的半透明层，而不是吃掉固定一条的实色栏。

**窗口本身是透明的，并挂了 Windows 11 的 Mica 背板**（`tauri.conf.json` 的
`transparent: true` + `windowEffects.effects: ["mica"]`）。所以下面这些 alpha 不是「在自己的底色上
再糊一层」的装饰，而是**真的把桌面透出来**的那一层。`body` 因此是 `transparent` —— 标题栏 / 侧栏 /
内容面三者各自按自己的材质重量铺满整个窗口，任何一处实色底都会把效果抵消掉。

色值以 `R G B` 通道三元组存放（`--canvas-rgb` / `--surface-rgb` / `--raised-rgb`），
同一个颜色的不透明版与半透明版由此共用一个来源 —— 旧版 `--material-sidebar` 是一个手写的
`rgba()` 字面量，已经和 `--canvas` 悄悄对不上了。

| Token | 底色 | alpha token | 默认值 | 用途 |
|-------|------|-------------|--------|------|
| `--material-chrome` | `--surface-rgb` | `--glass-chrome` | 0.66 | 标题栏、粘性区段头 |
| `--material-sidebar` | `--canvas-rgb` | `--glass-sidebar` | 0.56 | 侧栏（最薄 —— 它是结构，应当退后） |
| `--material-content` | `--canvas-rgb` | `--glass-content` | 0.86 / 深色 0.88 | 内容面（最厚 —— 阅读发生在这里） |
| `--material-popover` | `--raised-rgb` | `--glass-popover` | 0.86 | 弹出层、下拉、Toast |

模糊：`--blur-chrome: blur(20px) saturate(180%)` / `--blur-sidebar: blur(24px) saturate(140%)` /
`--blur-popover: blur(28px) saturate(180%)`。

规则：**绝不把浅色半透明层叠在另一个浅色半透明层上**（可读性会崩）。
**卡片因此是实色的** —— 它下面的内容面已经是半透明材质，卡片再半透明就正好踩中这条禁令。
面积越大的层，模糊越强、阴影越深。

**关掉玻璃有三个独立信号，全部落到同一个结果**：用户自己的「偏好设置 → 外观 → 窗口毛玻璃」
（`lib/glass.svelte.js`，写 `[data-translucent="off"]` 并调用 Tauri 的 `clearEffects()`）、
`prefers-reduced-transparency: reduce`、`prefers-contrast: more`。
三者都只把四个 `--glass-*` 压成 1 并去掉 blur —— 压 **alpha** 而不是逐个重写 `--material-*`，
意味着以后新增一层材质会自动被覆盖，不需要有人记得回来补。

> Mica 跟随**系统**深浅色，不跟随本应用的「外观」覆盖项。用户强行反着设时背板会偏向另一侧，
> 这是所有 Mica 应用的共同行为；上面的 alpha 取值保守到足以让文字对比度扛住，
> 真不喜欢的出口就是那个开关本身。

### 2.5 高度（Elevation）

| Token | 用途 |
|-------|------|
| `--elev-1` | 卡片静置 |
| `--elev-2` | hover / 拖起 |
| `--elev-3` | 弹出层、下拉、Toast |
| `--elev-4` | 模态对话框 |

深色模式的阴影需要额外加一层顶部亮边（`inset 0 1px 0 rgb(255 255 255 / 0.04)`）来替代

## 3. 排版

系统字体优先（Apple §15：系统字族自带光学尺寸、字距表与易读性调优）。
`font-variant-numeric: tabular-nums` 用于所有序列号、固件号、电平百分比、电量数字 —— 数字跳动时不能抖。

### 3.1 字阶（含尺寸相关字距）

**没有任何低于 12px 的文字。** 旧代码里 9px/10px/11px 的标签全部上移。

| Token | 尺寸 / 行高 / 字距 / 字重 | 用途 |
|-------|--------------------------|------|
| `--type-display` | 28px / 1.15 / **-0.02em** / 700 | 空状态大标题（唯一一处） |
| `--type-title` | 20px / 1.25 / **-0.015em** / 650 | 区段标题（h1） |
| `--type-title-sm` | 16px / 1.35 / **-0.01em** / 620 | 卡片标题（h2） |
| `--type-body` | 14px / 1.5 / **0** / 400 | 正文、控件标签 |
| `--type-body-strong` | 14px / 1.5 / **0** / 550 | 设置项标题 |
| `--type-caption` | 13px / 1.5 / **0.005em** / 400 | 说明文字、提示 |
| `--type-label` | 12px / 1.4 / **0.06em** / 600 / uppercase | 分组眉标（唯一允许 uppercase 的一档） |

Apple §15 的核心：**字距必须随字号变化，不能一个值套所有尺寸**。
大字收紧（负字距），正文归零，小字微微放开。旧代码把 `0.05em` 同时用在 11px 和 13px 上。

### 3.2 规则

- 层级由「字号 + 字重 + 行高」三者共同构成，不能只靠字号。
- 标题层级严格递进：区段 `h1` → 卡片 `h2` → 卡内小节 `h3`。全应用**每屏只有一个 h1**。
- 间距用 `rem`/`em`，跟随用户的系统字号缩放（Dynamic Type 等价物）。
- 长文本量度上限 `72ch`。
- **图标带头、后面跟着可换行文字的那种行，一律用 `.u-icon-line`**（app.css）。
  它是 `align-items: flex-start` 加一个按行高算出来的光学微调，把图标压在**第一行**上。
  曾经有四个组件各抄了一份 `align-items: center` —— 一行时看着对，两行时图标停在段落中间。

## 4. 间距、圆角、图标

### 4.1 间距（4/8 节奏，密度档 6/10）

`--space-1:4px` `--space-2:8px` `--space-3:12px` `--space-4:16px` `--space-5:20px`
`--space-6:24px` `--space-8:32px` `--space-10:40px` `--space-12:48px`

垂直节奏分层：卡内行距 `--space-3` → 卡内小节 `--space-5` → 卡间 `--space-6` → 区段间 `--space-10`。

### 4.2 圆角

`--radius-xs:4px` `--radius-sm:6px` `--radius-md:10px` `--radius-lg:14px` `--radius-xl:20px` `--radius-full:999px`

规则：圆角随尺寸走 —— 小控件 sm，卡片 lg，对话框/浮层 xl，胶囊 full。
（旧代码有 6/7/8/10/12/18px 六种硬编码值混用。）

### 4.3 图标

- **唯一策略：内联 SVG**，24×24 viewBox，`stroke-width: 1.6`，`stroke-linecap/linejoin: round`，
  `fill: none`，颜色一律 `currentColor`。
- 尺寸 token：`--icon-sm:16px` `--icon-md:20px` `--icon-lg:24px`。**不允许出现第四种尺寸。**
- **`display: inline-block`，不是 `block`。** 块级 SVG 掉进行内上下文（`<span>文字<Icon/></span>`）
  会强行自己占一行 —— 概览「全部音频设置」按钮的箭头掉到第二行就是这么来的。
  flex / grid 会把子元素块级化，所以这个改动对现有布局零影响，只修好了行内那一种情况。
- **禁止 emoji 当图标**（明确的反模式）。旧代码里的 `🔒`（锁定）和 `⚠`（备注）必须换成 SVG。
- 同一层级不混用描边/填充两种风格。
- **图标承担导航与语义识别，不是装饰**，出现在四个固定位置：
  侧栏条目 / 区段头（与侧栏同一个字形，来自同一条 `nav.js` 记录）/ 卡片头（`Card` 的 `icon`，
  颜色跟随 `tone`）/ 设置行（`Row` 的 `icon`；映射表在 `SettingRow.svelte`，
  按 `Setting.id` 而非由调用方传入 —— id 是同一个设置在三块屏幕上唯一稳定的东西，
  传 prop 就得抄三份并必然漂移；查不到的 id 落回 `sliders`，新机型不改这里也能正确渲染）。
  两个「15 分钟自动关机」共用 `clock` 是有意的：图标标记的是设置的**种类**，
  具体是哪台设备由标签负责说。
- 设备渲染图（PNG 精灵图 / `import.meta.glob` 的产品图）不属于图标体系，保持原样，
  但必须有 `alt` 或 `aria-label`。

### 4.4 触达尺寸

**所有可交互元素的命中区 ≥ 32×32px**（桌面指针场景下的下限；图标视觉尺寸可以更小，靠 padding 撑开）。
标题栏窗口按钮沿用 Windows 惯例（46×32），但其余一律 ≥32。
旧代码的 22px 高标签页、24px 图标按钮、9px 字的色板按钮全部不达标。

## 5. 动效

Apple §1–§11。核心信条：**动效表达行为，不是装饰**；**从当前呈现值出发**；**可被打断**。

### 5.1 Token

| Token | 值 | 用途 |
|-------|-----|------|
| `--dur-press` | `90ms` | 按下反馈 |
| `--dur-fast` | `160ms` | hover、颜色、透明度 |
| `--dur-base` | `240ms` | 区段切换、浮层进出 |
| `--dur-spring` | `480ms` | 配 `--ease-spring` 使用（见下） |
| `--ease-out` | `cubic-bezier(0.22, 1, 0.36, 1)` | 默认缓出 |
| `--ease-in-out` | `cubic-bezier(0.65, 0, 0.35, 1)` | 可逆双向过渡 |
| `--ease-spring` | `linear(0, .114, .319, .514, .669, .781, .859, .910, .944, .965, .979, .987, .992, .995, .997, .998, 1)` | **临界阻尼弹簧**（damping 1.0，response 0.35s），采样自 `x(t)=1-(1+ωt)e^{-ωt}`，无过冲 |
| `--ease-momentum` | `cubic-bezier(0.34, 1.4, 0.44, 1)` | 仅用于「手势带着动量」的场景（本应用几乎用不到） |

> `--dur-spring` 数学上是 480ms，但弹簧的**感知时长**远短于其完全静止时间：
> 上表采样点显示 ~43% 处（约 210ms）已走完 90% 行程 —— 正落在 150–300ms 的推荐区间里。
> 这就是为什么弹簧不能按「固定时长」来判断。
>
> `linear()` 缓动需要 Chromium 113+；Windows 上 Tauri 走 WebView2（常青版），远超此要求。
> 万一不支持，自定义属性在计算值阶段失效会退回 `ease`，是可接受的降级。

### 5.2 规则

- **反馈发生在 pointer-down，不是 click。** `:active { transform: scale(0.97) }`，`--dur-press`。
  唯一例外是标题栏的三个窗口按钮：它们的职责就是**填满窗口边角**，按下时缩放会把刚填满的角又露出来，
  所以那三个只用更深的填充色表达按下。
- **只动 `transform` 和 `opacity`。** 两处曾经违反：
  - `Meter` 的遮罩过渡 `left`。概览页 250ms 轮询意味着这个布局属性每秒被重排四次 ——
    现已改为 `transform: translateX(pct%)`（百分比相对自身宽度＝轨道宽度，几何完全等价）。
  - 侧栏折叠过渡 `width`。**这一条是明知故犯的例外**，写在这里而不是留在代码里当暗坑：
    内容列本来就必须重排才能收回那 232px，任何纯 transform 的写法都会让动画的某一端内容宽度是错的。
    真正省下来的是贵的那一半 —— `.sidebar-inner` 保持整宽并 `translateX` 滑出，
    侧栏自身的内容一帧都不重排，观感也从「就地被逐渐揭开」变成「从边缘后面滑出来」。
- **选中态是一个会动的物体，不是两个背景色的交接。** 侧栏导航用一个 `.marker` 绝对定位块在条目间滑动
  （和 `Segmented` 的指示块同一套道理），位置靠 `offsetTop/offsetHeight` **实测**而非按序号算 ——
  这样标签换行或用户放大系统字号时仍然对得上。`.nav-item.active` 因此不带自己的背景：
  带了就会在滑动的那段时间里同时亮起两块。
- 进出走同一条路径（Apple §7 空间一致性）：从右侧滑入的面板必须从右侧滑出。
- 浮层的 `transform-origin` 必须锚定在触发它的元素上。
- 玻璃材质进出要「材质化」而非纯淡入：同时动 `blur` 半径和 `scale`。
- 数值型指示（电平表、电量）走 `--dur-fast` 线性过渡，不用弹簧 —— 弹簧会让读数看起来在撒谎。

### 5.3 无障碍降级（三个独立信号，全部必须处理）

```css
@media (prefers-reduced-motion: reduce) {
  /* 位移/缩放/弹簧 → 短促交叉淡入。保留有助理解的透明度变化。 */
}
@media (prefers-reduced-transparency: reduce) {
  /* 半透明材质 → 提高底色不透明度并去掉 blur。 */
}
@media (prefers-contrast: more) {
  /* 近实色背景 + 明确的高对比描边。 */
}
```

## 6. 组件契约

全部放在 `gui/src/lib/ui/`，**只依赖 token，不依赖业务数据**。

**响应式一律用容器查询，不用视口媒体查询。** 会随内容列宽度变化的规则（`Row` 的堆叠断点、
`Card` 头部换行、`Section`/`SectionHeader` 的内边距）全部写成 `@container content (…)`，
容器由 `App.svelte` 的 `.content` 用 `container: content / inline-size` 建立。
理由是实测出来的：窗口最小宽度 760px 时，侧栏展开后内容列只有约 520px，
而 `@media (max-width: 640px)` 在那一刻根本不触发 —— 于是带四个选项的分段控件
正好在它本该堆叠的尺寸上被挤成一团。视口只该管真正与窗口有关的事（例如 720px 以下侧栏改为浮层）。

| 组件 | 契约要点 |
|------|----------|
| `Icon.svelte` | `{ name, size = "md" }`，内联 SVG 表，`currentColor`，`aria-hidden` 默认 true，`display: inline-block` |
| `Button.svelte` | `{ variant, icon, iconEnd, spin, busy }`。**尾随图标必须走 `iconEnd`**，不能塞进 children —— 它属于按钮的布局而非标签，塞进去会参与标签的换行；`spin` 让前置图标自转（「同一个动作，进行中」），而不是换成 spinner（「现在换了件事」） |
| `Fact.svelte` | `.u-facts` 里的一格：`{ label, icon, mono = true, clamp }`。五个组件曾各手写一遍 `div > dt + dd`，其中一份已经悄悄丢了 tabular-nums |
| `Switch.svelte` | `role="switch"`，`aria-checked` 支持 `"mixed"`；命中区 ≥32px；轨道/滑块用弹簧；**唯一实现**（现在 SettingControl 与 NoiseCancelControl 各抄了一份且已悄悄分叉） |
| `Segmented.svelte` | `role="radiogroup"`，方向键可移动；选中指示块用 `transform` 滑动而非切换背景色 |
| `Card.svelte` | `{ title, subtitle, icon, tone, actions }`，渲染真实 `h2`；`--elev-1`；**实色**（见 §2.4）；`icon` 的配色跟随 `tone` |
| `Row.svelte` | 设置行：主题字形 + 标签 + 说明 + 右侧控件 + **写入状态位**（见 §7） |
| `Field.svelte` | 标签在控件上方或左侧且**始终可见**（禁止 placeholder 当标签） |
| `Meter.svelte` | 电平表；`role="meter"` + `aria-valuenow`；渐变来自 token |
| `StatusDot.svelte` | 状态点，**必须带同义文字**，不靠颜色单独表意 |
| `Toast.svelte` / `toasts.js` | 右下角堆叠；成功 `role="status"`、错误 `role="alert"`；**绝对定位，不推动布局** |
| `Dialog.svelte` | 模态；焦点陷阱 + 返回焦点；`Esc` 关闭；遮罩 40–60% 黑；仅用于破坏性确认 |
| `Popover.svelte` | 锚定到触发元素；`transform-origin` 指向锚点；点击外部/`Esc` 关闭 |
| `EmptyState.svelte` | 图标 + 标题 + 一句说明 + 一个明确行动 |
| `SectionHeader.svelte` | 粘性、半透明、滚动边缘渐隐（**不是** 1px 硬分隔线），且只在真的有内容滚到下面时才出现 —— 状态由滚动容器 `.content` 以继承的 `--scroll-edge` 自定义属性下发，不穿三层组件传一个布尔值 |

## 7. 反馈体系（四类，缺一不可）

Apple §16：反馈分**状态 / 完成 / 警告 / 错误**四类，各有其位置。

| 类型 | 位置 | 形态 |
|------|------|------|
| **状态**（持续） | 就地 | 侧栏设备点、连接徽章、实时电平、模型「训练中…」 |
| **完成**（瞬时） | 控件右侧的状态位 | `写入中` 转圈 → `已生效` 对勾（1.2s 后淡出） |
| **警告** | 就地贴着相关控件 | 「两个发射器状态不同」、「需要 v2 协议」、电量低 |
| **错误** | Toast（右下角） | `role="alert"`，含具体原因 + 「重试」按钮 |

**关键修复**：旧版把错误塞进正常文档流的 banner 里，插入时把整页往下推（布局抖动）。
新版一律用绝对定位的 Toast 栈，永不改变布局。

**每一次写入都必须有可见的中间态。** 旧版从点击到设备确认之间，除了 `cursor: progress`
什么都没有 —— 用户无法区分「正在写」和「点了没反应」。

**破坏性操作**（`mic_tap_restore_factory_model` 恢复出厂模型）必须走 `Dialog` 确认，
文案写明后果（「本地增量学习成果将被清除」），并说明该操作本身也可撤销
（后端会先备份即将被替换的文件）。

## 8. 数据与轮询策略

- 窗口隐藏到托盘时（`document.visibilityState !== "visible"`）**暂停所有轮询**。
  旧版无论窗口是否可见都以 250ms 恒定轮询，托盘常驻场景下纯属浪费。
- 分级轮询：`概览`（含实时电平）250ms；其余设备区段 1s；训练状态 2s；不可见时 0。
- 乐观更新必须有**超时兜底**：超过 3s 未被设备确认则退回真实值并报错，
  不能像旧版那样把 `noise-cancel-power` / `noise-cancel` 的 per-TX 乐观值永久留在内存里。
- `error` 状态必须能被清除（Toast 自动消失 / 用户手动关闭），不能一直挂着。

**已知的有意保留项**

- 扇形快捷菜单（`PieMenu.svelte`）的开合动画仍是手写 rAF 弹簧（`stepEase`），没有换成 CSS token 里的
  `--ease-spring`。它本来就满足「可随时打断、从当前值继续」这条最重要的原则，换成 CSS 过渡反而会退化；

- 菜单项本身仍只显示图标，不显示文字标签——弧形几何尺寸由 Rust 侧（`pie_menu.rs`）计算，加文字会牵动

- `shortcut.rs`（接收器按键重映射）在 Windows 上始终不可用，是从已删除的 macOS 实现留下的占位模块。
  它没有被给一个区段——一个永远显示「不可用」的导航项只是噪音。
